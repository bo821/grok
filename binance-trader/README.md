# 币安 USDT 永续自动交易脚本

这是一套在 Windows 上运行的币安 USDT-M 永续合约短线脚本。主脚本每次运行会：读取账户和持仓 → 管理已有仓位（或在冷却后扫描开仓）→ 把状态写进本地文件，并在结尾打印 `===RESULT===` 块。

**风险声明：这是测试阶段的实盘脚本，会用真实资金下单，存在本金亏损的可能，不构成投资建议。** 近期实盘并不理想。例如 2026-11-12 的白天场次共 7 笔，按钱包口径从开场约 7.17U 到收盘约 6.04U，净亏大约 1.12U。脚本自己估算的已实现盈亏不可靠，平仓净盈亏应以「该笔开仓前钱包 − 平仓后钱包」为准。

本仓库是公开的，**不要把 API 密钥、账户状态或成交记录提交上来**。密钥只放在本地的 `keys.json`（不入库），可参考 `keys.example.json`。

## 文件说明

| 文件 | 作用 |
|---|---|
| `day_trade_run.ps1` | 主脚本：持仓管理、扫描、开仓、写状态 |
| `night_lib.ps1` | 公共函数：签名请求 `Call-S`、公开行情 `Call-P`、以及 `EMA` / `RSI` / `ATRpct` |
| `day_trade_status.ps1` | 只读查看钱包、持仓和条件止损单 |
| `keys.example.json` | 密钥文件模板（复制为 `keys.json` 后填入自己的密钥） |
| `day_state.json` | 运行时状态（本地生成，已加入 `.gitignore`） |
| `day_trades.csv` | 开平仓/移止损流水（本地生成，已加入 `.gitignore`） |

说明：`day_trade_run.ps1` 来自实际部署的版本，已去掉本机路径和电脑名。原先的 `night_lib.ps1` 只在交易电脑上，整理仓库时该电脑离线，未能直接复制；仓库里这份是按主脚本实际调用的接口重写的干净版本，只从本地 `keys.json` 读密钥，不打印密钥内容。指标计算若与原库有细微差别，以实盘验证为准。

脚本需保存为 **UTF-8 带 BOM + CRLF**，否则 Windows PowerShell 5 可能解析失败。

## 每次运行在做什么

外部调度器每隔约 5 分钟调用一次 `day_trade_run.ps1`。脚本自己也会看 `day_state.json` 里的 `last_scan_at`：距上次扫描不足 5 分钟则跳过扫描（`scan_skipped`），但仍会处理已有持仓。

流程如下。

### 1. 读账户和持仓

- 用签名接口读取钱包、可用余额、持仓和未完成条件单。
- **跳过 ETHUSDT**（持仓和条件单都不由本脚本管理）。同一账户若另有 ETH 策略，互不干涉。
- 非 ETH 持仓默认只管理第一笔（同时只开一笔）。

### 2. 若发现仓位已平掉

若状态里还记着开仓，但交易所已无仓位，视为已平（止损或其他原因）。冷却：估盈 ≥ 0 则 15 分钟，否则 20 分钟。脚本会用 `/fapi/v1/income` 的已实现盈亏做估算，但如前所述，这个数字不可靠。

### 3. 管理持仓

止损是 `STOP_MARKET` 条件单（`/fapi/v1/algoOrder`），触发价类型为 `MARK_PRICE`，`reduceOnly=true`。

开仓后的前 15 分钟，**只用止损单保护**，不因 15 分钟反向或 1 小时翻转提前平仓。15 分钟之后：

- **15m_against**：上一根已收盘的 15 分钟 K 线是反向实体，且实体幅度 ≥ 0.4%，则市价平仓。
- **1h_flip**：1 小时 EMA20 / EMA50 趋势已翻向，且当前浮盈 < 0.15U，则市价平仓。
- **max_hold**：持仓满 90 分钟且尚未锁利，则市价平仓。
- **tp_3pct**：浮盈幅度 ≥ 3%，且并非「已锁利且浮盈 > 0.4U」，则市价平仓。

持仓保留时的止损调整：

- **保本**：浮盈达到 **+0.5%** 时，把止损移到开仓均价加上约 0.08% 的手续费缓冲（多单在均价上方，空单在均价下方）。
- **锁利**：当前浮盈 ≥ 0.5U，或本笔见过的最高浮盈 ≥ 0.5U 时进入锁利。当前浮盈仍 ≥ 0.5U 时，锁利下限大约保证还能留下 0.3U，并按标记价做追踪止损（默认约 0.6%；1 小时 ATR 较高时在约 0.5%–0.8% 之间收紧，且不会把止损往不利方向挪）。还会按峰值浮盈保留一半（ATR 很高时保留 60%，且不少于 0.3U）抬高/压低止损地板。止损只朝有利方向移动。
- **补止损**：如果发现当前仓位没有条件止损单，按开仓价约 0.8% 补挂一笔。
- 仓位数量或均价变化达到一定幅度时，会按新均价重算保本止损；数量变化 ≥ 10% 时会先解除锁利标记。

### 4. 冷却与开仓限制

- 空仓且未到冷却结束时间：本轮不再扫描开仓（`cooldown`）。
- **21:00（运行脚本的电脑本地时间）之后不再开新仓**（`AFTER_2100_NO_NEW`）。若本场已经有过成交或记过盈亏，会在状态里留下一次日终汇总（`day_done`）。
- 测试阶段：**每日亏损上限和每日笔数上限已关闭**；单笔风险仍按下面的仓位规则控制。
- 可用余额 < 1.5U 时不开新仓（`low_avail`）。

### 5. 扫描交易对池

候选条件（取成交额前 200 个，ACEUSDT 始终排在最前）：

- USDT 永续、状态 `TRADING`、上线超过 14 天
- 24 小时成交额 ≥ 1000 万 USDT，**或** 交易对是 ACEUSDT（即使成交额不够也纳入）
- 24 小时涨跌幅绝对值 < 40%
- **排除 ETHUSDT**

### 6. 入场过滤（只要 A 级）

1 小时与 15 分钟趋势必须同向，且 1 小时动量更明确：

- 1 小时：EMA20 与 EMA50 的方向，加上 EMA20 相对 4 根 K 线之前的斜率，必须一致（多或空）。
- 15 分钟：同样用 EMA20 / EMA50 和斜率，方向必须与 1 小时相同。
- 1 小时 EMA20 与 EMA50 的间距绝对值 ≥ 0.25%。
- 用**上一根已收盘的 15 分钟 K 线**确认方向（阳线才能做多，阴线才能做空），不追正在走的那根。
- 已收盘 15 分钟实体幅度绝对值 ≥ 0.8% 则跳过；同时 15 分钟价格相对 EMA20 的偏离不能太大，5 分钟 RSI(7) 也不能过热/过冷（多单 RSI < 65，空单 RSI > 35）。
- 还需要「RSI 钩子」或「贴近 EMA」两者之一：
  - 多：近 4 根 RSI 最低曾 ≤ 30，且 RSI 回升、当前 ≤ 45；或价格贴近 15 分钟 / 1 小时 EMA。
  - 空：近 4 根 RSI 最高曾 ≥ 70，且 RSI 回落、当前 ≥ 55；或价格贴近 EMA。
- 买卖价差 ≥ 0.1% 跳过；1 小时 ATR（百分比）> 3.2 跳过。

通过的品种按综合评分排序，从前到后尝试开仓，成功一笔即停止。

### 7. 仓位与杠杆

- 杠杆：该品种允许的最大逐仓杠杆，**最高 20 倍**。开仓前会尝试设置杠杆和逐仓（`ISOLATED`）。
- 止损距离按 1 小时 ATR 分档，再设 0.4% 下限：默认约 0.8%；ATR ≤ 0.7 时约 0.6%；ATR ≥ 1.5 时约 1.0%；ATR ≥ 2.5 时约 1.2%。
- **缩小仓位，而不是把止损收得更近**，以便把单笔净最大亏损（止损距离 + 约 0.25% 手续费/滑点缓冲）控制在预算内。
- 两档风险：
  - **普通档**：预算约 0.6U（成交额排名 > 100 时约 0.5U），上限约 0.7U。ACEUSDT 只走普通档。
  - **最高把握档**：评分 ≥ 2.6、价差 ≤ 0.02%、排名 ≤ 100、ATR 在 0.6–2.5、15 分钟偏离 ≤ 0.3%，且不是 ACEUSDT 时，预算约 1.0U。
- 保证金目标约为可用余额的 65%，最高不超过 90%。若按止损预算算出的仓位太大，会缩小仓位，因此实际保证金占用可以低于 65%。
- 数量太小、名义金额不够最小下单额、预估亏损超出上限、或保证金 < 0.5U，则跳过该品种。

### 8. 下单并写状态

- 市价开仓，约 0.8 秒后读取实际成交均价和仓位数量，再挂上面对应的条件止损。
- 若开仓过程中报错但发现仓位已经存在，会补挂止损并按已成交仓位写入状态（恢复逻辑）。
- 更新 `day_state.json`，向 `day_trades.csv` 追加一行，最后打印：

```
===RESULT===
action=...
handoff=...
trades=... realized=...
===OK===
```

`action` 常见值：`opened`、`hold`、`stop_BE_LOCK` / `stop_PROFIT_LOCK`、`closed_detected`、`closed_15m_against`、`closed_1h_flip`、`closed_max_hold`、`closed_tp_3pct`、`cooldown`、`no_setup`、`scan_skipped`、`after_hours_no_open`、`day_done`、`error` 等。`handoff` 是给外部通知用的中文说明（开仓、保本、锁利、平仓、缺止损、日终汇总等），需要的话由调度方转发。

## 如何运行

环境：

- Windows PowerShell 5（Windows 自带即可）
- 电脑要能直接访问 `https://fapi.binance.com`（部分网络环境会返回 HTTP 451，需要在可访问币安期货 API 的机器上跑）
- 币安 USDT 永续 API Key，权限需包含期货交易；建议使用专用于本脚本的密钥，并限制 IP

准备：

1. 把本目录放到某一文件夹，例如 `C:\GrokTrader`。
2. 复制 `keys.example.json` 为同目录下的 `keys.json`，填入自己的密钥。字段名用 `apiKey` / `apiSecret`，或 `key` / `secret`，两种都可以。
3. 用记事本或编辑器确认 `.ps1` 文件是 UTF-8（最好带 BOM）。

手动跑一轮：

```powershell
cd C:\GrokTrader
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\day_trade_run.ps1
```

只看账户和持仓：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\day_trade_status.ps1
```

定时运行（每 5 分钟）：

- Windows 任务计划程序：每 5 分钟启动上面的 `-File .\day_trade_run.ps1`；或
- 任何外部调度（例如已有的例程/看门脚本）按同样方式调用。

脚本使用运行它的电脑的本地时钟判断 21:00 截止和冷却时间。状态文件与脚本放在同一目录。如需重新开一场（清空当日计数、冷却和持仓记录），可改脚本顶部的 `$SessionName`，或删除 `day_state.json`（不会自动平掉交易所上已有的仓位）。

## keys.json 格式

```json
{
  "apiKey": "YOUR_BINANCE_USDTM_FUTURES_API_KEY",
  "apiSecret": "YOUR_BINANCE_USDTM_FUTURES_API_SECRET"
}
```

也可以写成 `"key"` / `"secret"`。不要把填好的 `keys.json` 提交到 Git。

## 不包含的内容

- 本仓库不含 API 密钥、账户 ID、历史成交 CSV 或运行状态。
- ETHUSDT 由另一套独立脚本处理，这里刻意跳过，也不包含那套代码。
- 不会自动开启夜盘或全天常驻；21:00 后只管理已有仓位、不再开新仓。要延长交易时段需要改脚本并自行安排调度。
